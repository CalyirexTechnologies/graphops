GraphOps

An estate read as a graph, so a security team can hunt before an incident instead of reconstructing one afterwards. It answers which routes run from the internet to something worth stealing, what is in reach the moment a system is taken, and which routes are new even when every single step on them looks ordinary.

It runs two ways over the same graph, in memory with no dependencies, and in Neo4j with plain Cypher. Both are checked against each other on every run.

The problem

Alerts arrive disconnected, and the joins are the reason

When an attacker takes a low-privilege endpoint and moves sideways, that shows up as many separate alerts. An analyst then spends hours putting the chain back together by hand.

A relational store needs a chain of joins to trace one multi-hop relationship such as an identity using an address, which reaches a service, which holds data. A graph holds that same chain as a path and walks it directly. That is why the four questions below are all one traversal each rather than four reporting pipelines.

Most teams also cannot answer the first question anyone asks during a live incident, which is what the blast radius is right now and which critical systems sit on the attacker's direct path from here.

The model

Every edge points the way an attacker travels

Nodes are what telemetry already names, which is addresses, identities, endpoints, systems, cloud services, weaknesses and the rules that fired. Edges are what happened between them.

Direction is the decision that matters most. A cloud trail records that an identity acted from an address. An attacker who holds the address gains the use of the identity, so the edge is stored address to identity. Stored the way the log reads, every path search stops dead at the first address, which is what happened the first time this was written.

Each edge kind carries its MITRE ATT&CK tactic, so a path reads as a kill chain rather than a list of names. The mapping is per edge kind, not per event, and a kind that cannot be mapped honestly carries nothing rather than something plausible.

Trust zones run left to right. Without them every node looks equally important.

Choke points

Five of the twelve routes cross one endpoint

A choke point is where validated routes converge. Closing /api/orders removes more ways in than patching any single weakness on this estate does.

It is counted over the enumerated routes rather than as betweenness centrality. Betweenness scores a node against all shortest paths in the graph, most of which start and end somewhere nobody cares about. The number a defender can act on is "this is on five of the twelve ways in", and that is a count.

PageRank is run separately and independently agrees, putting /api/orders top of the systems we actually control. External addresses are excluded from that ranking, because there is nothing to harden about an address that is already hostile.

Louvain community detection splits the estate into six segments. Two of them contain activity from the last day, and one of those two holds the nightly backups, which is how an analyst learns which part of the business is moving rather than reading node names.

Blast radius

During an incident the question changes

An analyst holding one alert does not need another score. They need the neighbourhood, and that is the question most teams cannot answer while the incident is still open.

16systems within three hops
of the order service

One of the sixteen is the card database, which makes this a reportable breach rather than a ticket.

The walk is undirected on purpose, because compromise does not respect the direction a relationship happened to be recorded in. Each system is reported at the shallowest hop that reaches it and never again, so the one-hop list is not inflated by longer walks that also arrive.

GraphOps6
Structure, not rules

The route no rule fired on

Five hours before this snapshot, an address that has never tripped a detection rule began using a deployment credential. That credential could already reach the nightly backups, so the address now can too.

Every individual step is ordinary, no rule covers any of them, and no rule ever would, because the route is what is new and a rule inspects events. It is computed by walking the graph as it is, walking it as it stood before the window, and taking the difference.

The flag is called unflagged_by_rules. An earlier version claimed "every step already known", which can never be false, since in a static graph a path of old edges is an old path. It was removed rather than kept as a number that always looks good.

Zero trust

Access held against access used

The graph carries both. ENTITLED edges come from the identity provider and say what a principal is allowed to reach. CALLED and SERVES edges come from logs and say what it actually reached. Comparing them is one query rather than a reconciliation project.

Six grants exist here, four have ever been exercised, and the two that have not both end at a crown jewel. The support desk can read the card database and the HR database, and nobody has ever needed to.

This is the pre-incident finding. Nobody has to be attacked for it to be worth fixing, and it is also, from slide 4, the cheapest way into this business.

The check earned its place immediately. Cypher first reported thirteen routes where the engine reported twelve, because two nodes can be joined by both an entitlement and an observed use, and Neo4j walked each separately while the engine collapsed them. That is one route through the estate, not two. A submission that only ever ran one engine would have shipped the wrong number without knowing it.

Honesty, and next

What is real here

Real

  • Every number in this deck is printed by the code, not drawn.
  • It runs with Python and nothing installed. Neo4j is optional and adds the Cypher path.
  • Both engines run on every demo and are compared.

Not real, said plainly

  • The business is invented and the addresses route nowhere.
  • The estate is hand-authored, so the numbers here are the numbers you get when you run it.
  • Louvain here is the local-moving phase, not the full algorithm with graph collapse. It is named that way in the code.

Next

  • Somebody has to name the crown jewels. The graph says what connects to what. Which systems matter is a business judgement, and inferring it from centrality returns the busiest node, which is usually a health check.
  • Streaming. The estate is rebuilt in a batch today. The same projection from a queue makes blast radius live rather than near-live.
  • Containment. Blast radius already names what to isolate first, which is the shortest distance between a detection and a contained incident.
  • More sources. Internal address ranges and an endpoint agent widen the graph well past what logs alone can see.
